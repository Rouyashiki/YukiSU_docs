# Lua 插件管理

当前 `main` 已在底部导航第二项提供“插件”页。这里管理的是由 `ksud` 执行的 Lua 插件，不是 Zygisk 模块、普通 KernelSU 模块，也不是管理器 APK 插件。

::: danger 插件拥有 Root 级能力
插件回调由 Root 用户空间执行，API 可以启动命令、读写文件、修改属性与 sysctl，并能启动常驻 daemon。安装插件应按安装 Root 脚本或原生模块的风险评估，不能因为代码是 Lua 就当成普通主题包。
:::

## 已安装插件页

页面当前支持：

- 从本地 ZIP 安装插件；
- 搜索，并选择“已启用优先”排序；
- 下拉刷新实际 `ksud plugin list` 状态；
- 启用或停用插件；
- 在 manifest 声明 Action 时运行 Action；
- 运行 manifest 声明的快捷操作；
- 编辑 manifest 声明的配置字段；
- 查看或清除独立插件日志；
- 卸载插件。

底部导航的插件角标来自已安装插件数量，不代表这些插件都已启用、依赖完整或执行成功。

无效 manifest 会在卡片上显示错误，并禁用 Action/快捷操作。管理器的本地文件复制还限制插件 ZIP 不超过 272 MiB；这个大小上限不是真实性或安全校验。

## 启停与依赖

`ksud` 在启用插件前校验 manifest 和依赖。若仍有已启用插件依赖某项插件，停用或卸载会被拒绝。

停用时，`ksud` 还会尝试终止该插件登记的 daemon。若回调仍在运行、运行树繁忙或 daemon 无法安全停止，操作可以失败。看到开关变化后仍应刷新页面并检查插件日志，而不是假设所有旧进程已经消失。

启用插件不会补跑已经错过的启动阶段。依赖 `post-fs-data`、`post-mount`、`service` 或 `boot-completed` 回调的功能，通常要等对应阶段再次发生；完整重启是最明确的验证边界。

## Action、快捷操作与配置

- **Action** 只在插件实际声明 Action 时显示；
- **快捷操作** 调用 manifest 指定的 Lua 函数；
- **配置** 把页面字段保存给该插件，是否立即读取新值由插件实现决定；
- **日志** 是插件自己的记录，不等于完整 `ksud`、内核或 logcat 日志。

一次手动 Action 成功只证明该回调这次返回成功，不证明启动回调、daemon 或最终系统效果都正常。

## 插件仓库

插件页右上角仓库入口可以浏览、搜索、安装、更新或重新安装仓库插件。仓库源页面可以启停、刷新、排序、添加和删除源。

当前管理器内置一个 **FolkPatch Plugin Mirror** 源。它可以停用，但作为内置源不能删除。用户添加的远程源必须使用 HTTPS；只有 `localhost`、`127.0.0.1` 或 `::1` 测试源允许 HTTP。仓库索引响应还受到 4 MiB 大小限制。

::: warning 仓库插件没有 YukiSU 签名背书
安装确认框明确说明：YukiSU 不验证仓库插件的作者身份或发布签名。HTTPS 只保护传输到所填域名，不证明域名、索引或 ZIP 值得信任。
:::

安装前至少检查：

1. 源地址与插件主页是否属于预期作者；
2. ZIP 的可复现哈希或发布签名；
3. manifest 的 ID、入口、依赖、回调、Action 与配置；
4. Lua 源码是否执行外部命令、下载代码、改系统属性或写关键路径；
5. 出问题时如何停用、卸载和恢复被修改的系统状态。

## 推荐验证顺序

1. 安装后先保持最小配置，确认卡片无 manifest/依赖错误。
2. 启用一个插件并刷新列表。
3. 先运行可审计的手动 Action 或快捷操作，查看插件日志。
4. 需要启动阶段时再完整重启，并同时保存 `ksud`/内核日志。
5. 若行为异常，先停用插件；确认 daemon 已停止后再卸载。

Lua 插件与普通模块可以同时改系统状态。排查时一次只变更一层，避免把插件回调、模块脚本和 YukiZygisk 注入混成同一个故障。

插件包布局、manifest、Lua API 与资源限制见 [Lua 插件](/modules/plugin/)。
