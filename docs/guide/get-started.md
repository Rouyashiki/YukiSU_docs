# 快速开始

这页只做一件事：把 YukiSU 装上，并确认最基本的 Root 能用。

管理器能修补镜像、安装 LKM，但它不会魔法般地让错误 KMI 变正确，也不知道每台设备到底从哪个分区启动。动手前，你仍然得认得自己的设备。

::: danger 先想好怎么救，再碰启动镜像
准备好当前固件的原厂镜像，并确认电脑还能进 bootloader / fastboot。刷错分区、刷错槽位或加载不匹配的 LKM，都可能让设备卡在开机阶段。
:::

## 先看你的设备合不合适

YukiSU 目前只支持下面这类设备：

- ARM64；
- GKI 2.0；
- Linux 5.10 及以上；
- LKM 模式，也就是 `CONFIG_KSU=m`；
- 内核带有项目需要的 Kprobes、Kretprobes 和 syscall tracepoints。

还要确认四件容易刷错的事：

| 要看什么 | 你需要知道什么 |
| --- | --- |
| KMI | 准备的 LKM 必须和当前内核 KMI 对得上 |
| 启动分区 | 设备实际使用 `boot`、`init_boot`，还是厂商自己的布局 |
| 槽位 | 现在从 A 还是 B 启动，OTA 后准备写哪一边 |
| 恢复 | 原厂镜像放在哪，设备不开机时怎么刷回去 |

只看到 `5.10`、`6.1` 之类的主版本远远不够。同一内核版本可以有不同 KMI、符号和厂商修改，别拿名字看起来差不多的 `.ko` 碰运气。

## 1. 下载需要的文件

从 [YukiSU Releases](https://github.com/Anatdx/YukiSU/releases/latest) 下载官方管理器。群文件、网盘转载和名字很像的仓库，能不碰就不碰。

你需要：

- **YukiSU Manager APK**：用来安装、授权、管理模块和看诊断；
- **匹配 KMI 的 YukiSU LKM**：也就是最终要加载进内核的 `kernelsu.ko`。

管理器内置资源里有匹配项就直接用。没有的话，为设备内核自行构建，具体见[内核集成](/dev/integration/)。“关掉版本检查再试试”不是解决方案。

## 2. 选对安装方式

管理器里有几个入口，名字相近，用途并不一样：

| 入口 | 什么时候用 |
| --- | --- |
| 直接安装 | 设备当前已经有 Root，要更新当前槽位 |
| 安装到未使用槽位 | A/B 设备刚做完 OTA，还没切到新槽位 |
| 选择镜像修补 | 第一次安装，或者想先生成镜像再手动刷入 |
| 选择本地 `.ko` | 使用设备专用或自己编译的 LKM |

第一次安装时，YukiSU 自己还没提供 Root，所以通常是拿当前固件的原厂镜像去修补，再按设备自己的方式刷入。如果你现在已经在用 Magisk、KernelSU 或其他 Root，可以从现有 Root 环境直接安装，但先看对应的[切换说明](/guide/switch/kernelsu/)。

这里不会给一条“所有手机通吃”的 fastboot 命令。真要是存在这种命令，厂商们也不会把 `boot`、`init_boot` 和 A/B 槽位玩出这么多花样。

## 3. 点开始前，再看一眼

修补或安装页面上的摘要别直接划过去。至少确认：

1. 输入镜像确实来自**当前固件**；
2. LKM 的 KMI 与目标内核一致；
3. 准备写入的分区和槽位没有选反；
4. 输出镜像与日志已经保存；
5. 出问题后有办法刷回原厂镜像。

管理器检测结果如果和设备维护者的文档对不上，先停。很多砖不是工具写坏的，而是用户非常自信地给了它一个错误目标。

## 4. 首次安装别折腾 SuperKey

官方管理器默认靠包名和 APK 签名认证，正常安装不需要填写 SuperKey。

| 选择 | 会发生什么 |
| --- | --- |
| 留空 | 使用官方管理器签名，推荐 |
| 设置 SuperKey | 额外允许用密钥认证管理器 |
| 禁用 APK 签名验证 | 签名不再作为回退，只剩 SuperKey，风险很高 |

SuperKey 只认证管理器，不是应用 Root 密码，更不是越复杂越“高级”的必开选项。真有自定义签名或私有管理器需求，再去看 [SuperKey 认证](/manager/superkey/)。

## 5. 写入和重启

确认目标无误后，再执行修补或安装。需要手动刷入时，使用设备或内核维护者给出的命令，不要从另一款手机的教程里抄一行 fastboot 命令。

重启前把这些东西留在电脑上：

- 当前固件的原厂镜像；
- 刚生成的修补镜像；
- 修补/安装日志；
- 能用的 platform-tools 或设备恢复工具。

如果第一次启动明显卡住，不要反复重启碰运气。按[救砖与恢复](/guide/rescue-bootloop/)刷回已知能启动的镜像，再看第一条错误。

## 6. 第一次开机先测 Root

开机后先别急着一口气装十几个模块。打开管理器，按顺序看：

1. 首页能识别 YukiSU，LKM 版本符合预期；
2. 管理器已经通过签名或你选择的方式完成认证；
3. 内置 `ksud` 与设备中安装的 `ksud` 没有明显错配；
4. 给一个可信测试应用授权，确认 `su` 能正常进入和退出；
5. 再重启一次，确认这些状态没有丢。

到这里，才算证明“LKM、`ksud`、管理器、应用授权”这条主链是通的。

## 7. 然后再加模块和 YukiZygisk

建议顺序：

1. 保留已有或安装一个适合设备的 MetaModule；
2. 重启，确认挂载后端正常；
3. 加入日常使用的普通模块；
4. 需要 Zygisk 模块时再开启 YukiZygisk；
5. Zygisk 模块逐个启用，至少知道出事时该先关谁。

这不是让你把手机当实验室做七轮对照组，而是别在第一次启动前同时换 Root、换挂载后端、装一堆模块再开 Zygisk。那样真出问题时，谁也猜不出是哪一层。

## 怎样算安装完成

- 重启后管理器仍能识别 LKM；
- 只有你授权的应用能拿 Root；
- `ksud` 与管理器/LKM 版本正常；
- MetaModule 能把需要的模块文件挂出来；
- YukiZygisk 关着时，Root 和普通模块照样工作。
