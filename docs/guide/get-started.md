# 快速开始

这页只做一件事：把 YukiSU 装上，并确认最基本的 Root 能用。

管理器能修补镜像、安装 LKM，但安装前先确认目标 KMI、启动分区和槽位。下面按这个顺序操作。

::: danger 先想好怎么救，再碰启动镜像
准备好当前固件的原厂镜像，确认设备能进入 bootloader / fastboot，且电脑能识别设备。刷错分区、刷错槽位或加载不匹配的 LKM，都可能让设备卡在开机阶段。
:::

## 先看你的设备合不合适

YukiSU 目前只支持下面这类设备：

- ARM64；
- Android 12（API 31）及以上；
- GKI 2.0；
- Linux 5.10 及以上；
- LKM 模式，也就是 `CONFIG_KSU=m`；
- 内核能加载模块，并带有项目需要的 Kprobes、Kretprobes 和 syscall tracepoints。

还要确认四件容易刷错的事：

| 要看什么 | 你需要知道什么 |
| --- | --- |
| KMI | 准备的 LKM 必须和当前内核 KMI 对得上 |
| 启动分区 | 设备实际使用 `boot`、`init_boot`，还是厂商自己的布局 |
| 槽位 | 现在从 A 还是 B 启动，OTA 后准备写哪一边 |
| 恢复 | 原厂镜像放在哪，设备不开机时怎么刷回去 |

只看到 `5.10`、`6.1` 之类的主版本远远不够。同一内核版本可以有不同 KMI、符号和厂商修改，别拿名字看起来差不多的 `.ko` 碰运气。

当前标准构建覆盖 Android 12/5.10 到 Android 17/6.18 的 8 个 KMI 目标，但系统版本和内核世代不是一一对应。先看[兼容范围](/guide/compatibility/)里的完整表，再按目标内核或 `boot` 镜像选择。

## 1. 下载需要的文件

从 [v1.8.0 发布页](https://github.com/Rouyashiki/YukiSU/releases/tag/v1.8.0)下载 `YukiSU_v1.8.0_10670-arm64-v8a-release.apk`。`.asc` 是签名文件，Source code 是源码压缩包，都不能作为 APK 安装。

完整 Manager 构建内置 8 个标准 KMI LKM。单目标构建只含选定的 KMI；下载后先确认安装页能选到你的目标。准备以下文件：

- **YukiSU Manager APK**：用来安装、授权、管理模块和看诊断；
- **当前固件的原厂启动镜像**：首次安装与恢复都要用；
- **单独的匹配 KMI LKM（按需）**：只有内置资源没有目标、或设备必须使用专用构建时才需要手选 `.ko`。

管理器内置资源里有匹配项就直接用。没有的话，为设备内核自行构建，具体见[内核集成](/dev/integration/)。“关掉版本检查再试试”不是解决方案。

## 2. 选对安装方式

管理器里有几个入口，名字相近，用途并不一样：

| 入口 | 什么时候用 |
| --- | --- |
| 直接安装 | 设备当前已经有 Root，要更新当前槽位 |
| 安装到未使用槽位 | A/B 设备刚做完 OTA，还没切到新槽位 |
| 选择镜像修补 | 第一次安装，或者想先生成镜像再手动刷入 |
| 下载镜像 | HTTPS 地址指向可 Range 读取的 OTA/factory ZIP 或 `payload.bin`，希望只提取一个启动分区 |
| 选择本地 `.ko` | 使用设备专用或自己编译的 LKM |

设备还没有 Root 时，选择当前固件的原厂镜像进行修补，再按设备的刷写步骤写入。如果你现在已经在用 Magisk、KernelSU 或其他 Root，可以从现有 Root 环境直接安装，但先看对应的切换说明。

本地修补、直接安装和 OTA 安装可选择传统 Ramdisk 或 ImgPatch 内核直嵌布局；两者改的分区、输入限制与恢复方式不同。ImgPatch 只能修补含 ARM64 kernel 的 `boot`，远程镜像入口当前只走传统模式。先读[安装与镜像模式](/guide/install-modes/)，再决定是否打开“将 LKM 直接嵌入 boot 内核”。

安装页的高级选项还包括启动配置与“仅配置”修补。首次获取 Root 应保留正常 LKM 安装；仅配置模式不安装 LKM，见[启动配置](/manager/boot-config/)。

## 3. 点开始前，再看一眼

修补或安装页面上的摘要别直接划过去。至少确认：

1. 输入镜像确实来自**当前固件**；
2. LKM 的 KMI 与目标内核一致；
3. 选择的是 Ramdisk 还是 ImgPatch，而且输入分区符合该模式；
4. 准备写入的分区和槽位没有选反；
5. 已准备输出镜像与日志的保存位置；直接安装只保存日志，不会额外导出镜像；
6. 出问题后有办法刷回原厂镜像。

管理器检测结果和设备维护者的说明不一致时，先停止安装，确认固件版本、启动分区和目标槽位后再继续。

## 4. 首次安装别折腾 SuperKey

官方管理器默认靠包名和 APK 签名认证，正常安装不需要填写 SuperKey。

| 选择 | 会发生什么 |
| --- | --- |
| 留空 | 使用官方管理器签名，推荐 |
| 设置 SuperKey | 额外允许用密钥认证管理器 |
| 禁用 APK 签名验证 | 签名不再作为回退，只剩 SuperKey，风险很高 |

官方管理器首次安装时把 SuperKey 留空。使用自定义签名或私有管理器时，再按 [SuperKey 认证](/manager/superkey/)配置。

## 5. 写入和重启

确认目标无误后，再执行修补或安装。需要手动刷入时，使用设备或内核维护者给出的命令，不要从另一款手机的教程里抄一行 fastboot 命令。

重启前把这些东西留在电脑上：

- 当前固件的原厂镜像；
- 通过镜像修补生成的输出文件；直接安装和 OTA 槽位安装不会额外导出这个文件；
- 修补/安装日志；
- 能用的 platform-tools 或设备恢复工具。

如果第一次启动明显卡住，不要反复重启碰运气。按[救砖与恢复](/guide/rescue-bootloop/)刷回已知能启动的镜像，再看第一条错误。

## 6. 第一次开机先测 Root

开机后先别急着一口气装十几个模块。打开管理器，按顺序看：

1. 首页能识别 YukiSU，LKM 版本符合预期；
2. 管理器已经通过签名或你选择的方式完成认证；
3. 首页报告的 Ramdisk / ImgPatch / late-load 运行方式符合预期；
4. 内置 `ksud` 与 `/data/adb/ksud` 的实际完整性状态匹配；需要时从主页手动同步，自动同步默认关闭；
5. 给一个可信测试应用授权，确认 `su` 能正常进入和退出；
6. 再重启一次，确认这些状态没有丢。

这些检查通过后，就可以继续安装日常模块。

## 7. 然后再加模块和 YukiZygisk

建议顺序：

1. 先使用内置 Kagami；已有外部 MetaModule 时，确认当前挂载由哪个后端负责；
2. 安装一个可信模块，按要求重启并验证实际文件和功能；
3. 有特殊挂载需求时，再选择合适的外部 MetaModule 或显式配置 Kasumi 后端；
4. 需要 Zygisk 模块时开启 YukiZygisk，完整重启后逐个验证模块；
5. 一次性脚本、热安装和 preinit 按各自指南使用，不把它们当作普通安装的别名。

见[模块系统](/modules/overview/)与[挂载后端](/modules/magic-mount/)。一次只改变一个关键组件，便于定位失败来源。

## 怎样算安装完成

- 重启后管理器仍能识别 LKM；
- 管理器显示的运行方式与实际安装布局一致；
- 只有你授权的应用能拿 Root；
- 设备侧 `ksud` 与 APK 内置版本一致，运行中的 LKM 对应所选构建；
- 实际选择的 Kagami 或 MetaModule 能把需要的文件挂出来；
- YukiZygisk 关着时，Root 和普通模块照样工作。
