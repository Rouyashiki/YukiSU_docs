# 更新 YukiSU

## 从旧管理器升级到 v1.9.0

**第一次换到 v1.9.0，请手动安装新版 APK，先留着旧管理器。** 官方管理器的包名从 `com.anatdx.yukisu` 改成了 `org.rouyashiki.yukisu`，APK 签名证书也换了。Android 会把它们当成两个应用，所以安装后看到两个 YukiSU 图标是正常的。旧管理器的 CI 更新器无法完成这次升级。

1. **先留一份备份。** 记下自己添加的模块和插件仓库地址，把需要的备份导出到电脑或下载目录。再看一眼上次修补镜像的日志。如果原厂镜像备份只存在旧管理器的私有目录（`boot_backup/`），请先另外准备一份与当前固件匹配的原厂镜像。
2. **安装新版管理器。** 到 [v1.9.0 发布页](https://github.com/Rouyashiki/YukiSU/releases/tag/v1.9.0)下载 `YukiSU_v1.9.0_10745-arm64-v8a-release.apk`。如果分不清两个图标，长按图标打开应用信息，看版本是否为 **v1.9.0（10745）**。有些系统还会显示包名。
3. **按原来的方式更新内核模块（LKM）。** 如果平时刷启动镜像，用新版管理器安装与设备 KMI 匹配的 v1.9.0 LKM，再完整重启。旧内核可能只认旧签名。如果新版没有直接安装权限，可以用新版修补当前固件的原厂镜像，再按设备原有的方法刷入。分区和槽位的选择见[安装与镜像模式](/guide/install-modes/)。如果平时用的是[临时加载](/guide/jailbreak-mode/)，完整重启结束旧会话后，用新版重新加载即可。
4. **用新管理器确认升级成功。** 首页应能认出运行中的 v1.9.0 LKM。点开 `ksud daemon`，如果和内置版本不一致就点同步。再用一个你信任的应用试一次 Root，检查原来的模块和仓库。用 Kasumi 的话，顺手确认状态页显示 API 19。

### 哪些数据要自己搬

| 数据放在哪里 | 换包后怎么办 |
| --- | --- |
| `/data/adb` 下的全局数据，包括已装模块及其配置 | 继续使用原有数据。新管理器通过内核认证后就能读取，无需重新安装所有模块。 |
| 旧管理器自己的设置、仓库来源和私有备份 | Android 会把它们留在旧应用里。按原来的偏好重新设置、添加仓库，保留需要的备份后再卸载旧 APK。 |
| 自己设置并保存过的 SuperKey | 在新管理器中重新输入。系统备份和换机迁移都不包含这个密钥。使用官方签名认证的用户可以留空。 |

v1.9.0 的官方 LKM 同时信任新旧证书，方便过渡。新版 `ksud` 默认会打开新包名的管理器，Root 授权弹窗和后加载完成后返回的也是新版。确认迁移完毕后，如果想删掉旧图标，在 Android 的应用信息里卸载旧包。管理器里的“永久卸载”会移除设备上的 YukiSU。

### 升级后还能看到哪些变化？

- **用内置 Kagami 挂载模块时**，临时加载会先挂好模块文件，再运行后续脚本。卸载模块后还留着旧文件的问题也已修复。[模块挂载](/modules/magic-mount/)
- **YukiZygisk 显示“部分注入失败”时**，说明同一轮运行中既有成功也有失败。打开模块详情，看出问题的应用对应哪条记录。[YukiZygisk 状态](/yukizygisk/features/)
- **使用 Magisk su 兼容模式时**，如果“默认卸载模块”可能挡住授权弹窗，管理器会提醒你检查对应应用的设置。[功能控制](/manager/feature-control/)

## 以后怎么更新

正式版继续从 [GitHub Releases](https://github.com/Rouyashiki/YukiSU/releases) 下载。要试开发版，在新版管理器的设置里打开“检测 CI 更新”。它从 [CI 更新站](https://yukisuupdates.rouyashiki.org/)检查构建，核对仓库、包名、APK 签名和构建签名。

“自动更新 ksud”默认开启。如果冷启动时管理器已经通过内核认证，它会比较 APK 内置的 `ksud` 和设备上的 `/data/adb/ksud`。如果刚打开时还没认证，稍后可以在首页手动同步。这个开关只负责 `ksud`。

## 更新 LKM 和启动组件

先把当前固件的原厂镜像留在电脑上。保留原先的安装方式时，Ramdisk 按设备布局修补 `boot` 或 `init_boot`，ImgPatch 修补含内核的 `boot`。要切换方式，或修补时遇到备份恢复错误，请看[安装与镜像模式](/guide/install-modes/)。

直接安装会把结果写入目标分区，日志里能看到写到了哪里。需要留一份修补后的镜像文件，选“选择镜像修补”或“下载镜像”。LKM 和启动配置都要完整重启才生效，软重启不能加载新 LKM。

## OTA 后更新

“安装到未使用槽位”适用于 A/B 设备刚完成 OTA、还没重启切槽的时候。在安装页核对新槽位、分区和 KMI。管理器会从新槽位的 `boot` 读取 KMI。如果解析失败，先核对 OTA 和原厂镜像，再继续。

## 配置与模块一起升级时

平时开了启动强制配置、preinit，或设过内核模块黑名单，就在修补时把这些选项一起带上。“仅配置”会按这次勾选的内容重建配置。普通模块更新会在下次启动合并，有开机早期脚本的模块要完整重启才能看出效果。恢复 App Profile 备份时，先核对应用和用户，再应用原来的授权。[启动配置](/manager/boot-config/) · [应用配置备份](/manager/app-profile/)

## 从 v1.8.0 以前的版本升级

如果你跳过了 v1.8.0，还要检查以前改过的两处设置。默认 Root 域已改为 `u:r:ksu:s0`，首次迁移会开启 Feature 102。已有自定义 Profile 的域和标志会保留。WebView 的“卸载模块”已移到“超级用户 → WebView Zygote”，旧脚本或启动配置里的 Feature 5 和 100 可以移除。详见[应用配置](/manager/app-profile/)和[功能控制](/manager/feature-control/)。
